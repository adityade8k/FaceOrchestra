## Implemented behavior

- Root navigation is Play, Tutorials, Record Songs. Play starts empty or restores its saved workspace. Basics comes first; both song libraries use a lightweight, paginated registry. The existing Jog and Kuch guided lessons remain available, and both have prepared recording ensembles.
- `ApplicationModeRouter` serializes loading, Play checkpoints, preparation and rollback. `MenuController` owns visibility, pose and input capture. Left thumbstick click uses handedness and validated button 3 mappings; hold and axes do not repeatedly toggle. Either controller can grip the header. Trigger on the header returns Home. Desktop Menu / M, Home and Recenter controls are provided. The receiver setup retains Open Editor.
- Menu hiding preserves active lesson and recording state. Captured grip/trigger gestures are held until release so hiding cannot click through. Reconnecting with the stick already pressed requires release before the next toggle. Controller loss clears that hand's interaction and pending placement. Menu presentation follows the existing opt-in capture UI policy and is outside scene persistence and instrument contact/audio ownership.
- `CompositionRegistry` validates lazy-loaded, serializable definitions. Existing songs use compatibility adapters; `SongRecordingSession` owns readiness, count-in, one sync per attempt, restart, stop, durable finalization and interruption. Content identity/hash and arrangement provenance are recorded. Missing original MIDI bytes are never assigned an invented source hash.
- Play uses debounced timer checkpoints and IndexedDB structured-clone storage, with current/previous values in one transaction. Legacy localStorage data remains available for migration/recovery. Unavailable storage, quota, corrupt and unsupported data are explicit states. Partial restores block overwrites. Learning progress uses a separate versioned namespace.
- Automatic Looper completion marks Play dirty. XR interruption retains clock relationships, and restored Metronomes preserve their editing lock while remaining paused. Mode exit waits for an ongoing recording transition; application teardown cancels outstanding catalog preparation.
- Looper sockets derive parent-local −X/+X tangents from explicit left/right bank metadata. Track identities, front controls, forward anchor offset, arriving-end sign and wire geometry cache are retained. Preview and completed curves use the shared socket rule; new capture records the actual resulting wire. Old captures retain their historical geometry.
- Receiver mutations serialize per take. Read-only browsing does not open writers. Finalization closes writer handles and inactive writer caching is bounded. Durable metadata commits and connection-close draining precede shutdown. Assets use immutable SHA-256 objects hard-linked into the existing per-take portable directory layout, with a copy fallback across filesystems.
- Contact detection uses a conservative sweep over freshly sampled authoritative spheres. Existing contacts continue through exit debounce even outside the candidate set; separated pair records retire. Registry kind views cache membership only; visibility/pose/collider admission still uses current entity state.
- Repository and replay ownership inventories release shared resources at final teardown and handle late or failed loads. Capture disposal waits for finalization rather than destroying dependencies while a worker still owns unsaved data. Deferred main-thread resource encoding now has task budgets and separate metrics; an individual encoding operation is not preemptible.
- Replay keyframe lookup is binary and sequential replay reuses reconstructed state. Takes over 16 MiB use streamed byte indexes, HTTP Range requests and a three-chunk presentation cache. Short/old captures keep the existing timeline path. Take/project/video replacements have generation guards; failed replay replacements are disposed.
- Live playback skips unbounded catch-up after suspension while preserving the existing audio scheduling horizon and offline traversal semantics.
- The [MIDI workflow](../midi-import.md) preserves binary provenance, normalizes timing/expression, generates supported data-driven guided lessons, and connects a third synthetic composition without song-name checks in the core runner. Rejected re-imports leave current files unchanged; accepted versions retain hash-named normalized sources and compositions, plus the previous complete bundle.

It compares the original committed implementation with the working tree on the same separated-row fixtures. At 100 Honks, retained pairs changed from 4,950 to 0; p95 contact-update time was approximately 0.926 ms versus 0.011 ms. At 200 Honks, retained pairs changed from 19,900 to 0. These are isolated CPU measurements, not XR frame rates. Dense overlapping scenes still require many exact contact checks.

`browser.json` records Headless Chrome 153 with software rendering. The smoke test exercised both real ensembles, empty Play, menu visibility, 50 Basics/Play transitions and the third data-only MIDI tutorial. One rendered Jog scene contained 24 instruments, 264 draw calls and 296,902 triangles; Kuch contained 25 instruments, 271 calls and 305,094 triangles. These are workload observations, not measured gains or GPU budgets. Materials, shadows and rendering quality were not reduced.

Focused tests finalize 20 receiver takes with zero retained writers, exercise 20 serialized recording restarts, compare contact graphs over 180 moving/scaling/teleporting frames, verify bank directions and preview/completed wire parity, verify shared ownership, and compare indexed versus full replay over a synthetic 30-minute timeline. A 30-minute fixture is not a 30-minute browser/headset soak.

`long-editor.json` records a browser run with 18,000 samples spanning 1,799.9 seconds and a 39,307,894-byte sample stream. Initial load was approximately 568 ms; 66 verified random/sequential seeks measured p50 2 ms, p95 73.7 ms and p99 201.6 ms. Three chunks remained cached and concurrency is bounded to two range requests. This generated Group-node fixture exercises real HTTP Range loading and indexed reconstruction; it is not a realistic instrument/GPU workload or a live capture soak.

## Remaining validation and capability limits

- No physical headset, controller ergonomics, audible listening comparison, real phone-video session or GPU timer measurements were performed. Connector math and curve parity do not prove visual mesh alignment on the headset. The authored model was not rotated or its forward socket offset guessed.
- Real 2-, 10- and 30-minute capture/editor soaks, increasing audio voice/looper counts, and 72/90/120 Hz headroom remain unmeasured. Frame periods are 13.89/11.11/8.33 ms; no achieved refresh rate is claimed. Performance budgets need device measurements before enforcement.
- Earlier extended browser attempts encountered a software-rendered delayed-frame interruption, Chrome debugging disconnects during concurrent runs, and stale learner-flow assertions for the former two-looper layout. The final isolated Jog, Kuch and radial runs pass. Production timing guards were retained; the regression fixture now matches the existing three-loop arrangement and preserves the Recenter/Exit controls alongside switching actions.
- The importer normalizes broader MIDI features than it can automatically arrange. Variable-tempo, polyphonic live roles, percussion/pressure/MPE rendering and full orchestral supporting-role generation need explicit authored capability work. The command rejects unsupported automatic conversions rather than flattening or discarding them silently.
- Presentation sample memory is bounded by chunks; editor event/resource history still scales with the number of distinct recorded resources and events. Individual main-thread texture encodes may exceed their task budget. A fully streamed resource history and worker image encoding remain useful follow-up work.
- Long-take byte indexes are rebuilt by streaming on each load. This bounds memory but still incurs linear disk scanning; a persisted verified index is a further loading optimization.
- Shared assets deduplicate disk bytes, not GPU memory. New procedural assets continue through the recorded resource stream; files changed after receiver startup require restart. Arbitrary newly introduced external asset paths need a manifest-extension workflow before being considered portable.

This is a substantial local implementation with explicit remaining capability and hardware-validation limits; it is not evidence that every item in the requested full performance/soak matrix is complete.
